| Field | Value |
|---|---|
| Subject | Outcome-bearing work |
| Scope | A proposed, selected, continued, completed, or value-claimed work or information-expansion unit with a current Human Intent, Value Gap, applicable constraints, any supplied operating envelope, any current capability claim for a selected person, tool, module, or approach, any already-visible material external controller and supplied controlling condition or loss consequence, and any current rationale based on prior investment, an earlier plan, or an existing commitment |

| Failure evidence | At least one of the eight failure cues is present and the current packet does not connect that cue to its required value relation. For the capability-proxy form of option fit, a credential, visibility, general reputation, size, or unrelated prior result supports the selection while no relation to the required task role, operating conditions, or output is supplied. For the external-control form of option fit, the current packet already shows a material external controller and supplied controlling condition, but the option treats that condition as owned or stable or ignores an already-visible exit, switch, or loss consequence. | Success condition | The matched cue has its lifecycle-appropriate value relation: an option names its intended value, any capability claim used for selection is related to the current required role, operating conditions, and output, and any already-visible material external control or consequence is related to the option's current conditions; work names observable completion; support artifacts remain subordinate; realized value reaches the intended consumer or produces the desired-state change; the result remains usable across ordinary variation already inside the supplied operating envelope; each admitted information unit answers a current question, fills a current capability gap, supplies required evidence, or serves the named consumer while unrelated material is deferred; a proposed reusable structure is compared with current required fields, transitions, conditions, outputs, and operating conditions and only fitting parts are retained; or a continuation supported by prior investment, an earlier plan, or commitment is related to current conditions and expected Value Gap effect, with exit or reversal considered only when already material in the supplied scope |
| Success outcome | Work, continuation, or information expansion is selected, completed, and recognized for observable progress toward the desired state rather than for task-related activity, artifact production, information accumulation, or sunk history itself |
| Success evidence | The current option or result shows its relation to the Value Gap and constraints; a capability-based selection links the selected person, tool, module, or approach to the current required role, operating conditions, and output; an external-control selection relates the already-visible material controlling condition or consequence to current option fit; a realized-value claim includes intended-consumer use or the desired-state change; an ordinary-variation claim succeeds within the supplied operating envelope without unrelated redundancy; an information-expansion claim traces every admitted unit to a current use, question, capability gap, evidence need, or consuming operation; a structure-reuse claim shows that retained fields and transitions cover current requirements and excludes visible mismatches; a prior-investment rationale also shows the current conditions and expected Value Gap effect |
| Vibe scope cue | A proposed, selected, continued, completed, or value-claimed unit and the current Human Intent or Value Gap are available; the option-fit cue additionally includes a person, tool, module, or approach selected from a capability claim or a proposed result whose current packet already shows a material external controller and supplied controlling condition or loss consequence; an ordinary-variation cue additionally requires a supplied operating envelope; an information-expansion cue additionally requires a proposed or admitted source, term, topic, or note set; a structure-reuse cue additionally requires a prior template, workflow, module, process, or solution proposed for the current task; a sunk-history cue additionally requires prior investment, an earlier plan, or an existing commitment used in the current rationale |
| Vibe failure cue | Any one current-operation cue: activity or artifact production stands as completion; generic safety, quality, familiarity, prestige, default status, credential, visibility, general reputation, size, an unrelated prior result, or an externally controlled condition treated as owned or stable stands as option fit or capability proof while the required current relation is absent, or an already-visible material exit, switch, or loss consequence is ignored; standards conformity or an evidence-shaped artifact stands as task progress; existence, potential, completeness, or complexity stands as realized value without consumer use or desired-state change; nominal success depends on one exact timing, environment, input, or manual rescue despite ordinary variation already inside the supplied operating envelope; admitting sources, terms, topics, or notes stands as progress or value while no current use, open question, capability gap, evidence need, Value Gap trace, or consuming operation is bound; a prior structure is selected by familiar name or surface similarity while a visible current required field, transition, condition, output, or operating condition differs; or prior investment, an earlier plan, or an existing commitment supports the option while the current packet supplies neither a relation to current conditions nor an expected Value Gap effect |

| Failure evidence | The support path visibly eclipses the primary path, or the same boundary clarification, incompatibility, or repair recurs in the supplied scope; no proportionality calculation or proof is required |
| Success condition | The matched cue has its burden relation corrected: support stays subordinate to the primary action, or a bounded interface or convention prevents the same in-scope ambiguity or repair from recurring without creating unrelated framework work |

| Vibe failure cue | Either the support path grows past or obscures the primary path, or the same ambiguity, incompatibility, clarification, or repair recurs at that boundary |
